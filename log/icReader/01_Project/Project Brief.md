# Project Brief

Last reviewed: 2026-07-26

## Purpose

`icReader` is a small Python package for reading NetCDF ionospheric-conductance
products generated by `icBuilder`.

**Confirmed by the user:** its reader code and classes are used by
`icAnalyzer`. This makes the public reader behavior and product compatibility a
cross-project interface.

## Public interfaces

`icreader/__init__.py` exports:

- `ConductanceImage`, which loads direct conductance-orbit products and exposes
  sensor statistics, characteristic energy and flux, Hall and Pedersen
  conductance, uncertainties, time, and cubed-sphere grid coordinates;
- `SplineImage`, which loads spline coefficients, evaluates Hall and Pedersen
  conductance and uncertainties in time and space, and constructs
  coordinate-aware callable interfaces for downstream modeling.

`icreader/SplineFactorImage.py` contains a separate CHOLMOD-backed reader or
factor reconstruction path but is not exported by the package. Its intended
support status is not currently documented.

## Code map

- `icreader/conductanceimage.py`: direct conductance-product reader and
  in-memory time filtering.
- `icreader/splineimage.py`: spline-product reader, coordinate conversion,
  evaluation, and callable conductance interfaces.
- `icreader/SplineFactorImage.py`: unexported factor/covariance implementation
  requiring separate review.
- `example_data/conductance/`: tracked conductance NetCDF examples.
- `example_data/spline/`: tracked spline NetCDF examples.
- `scripts/`: manual loading, comparison, and plotting workflows; these write
  figures and are not automated tests.
- `log/icReader/`: project memory and historical spline-development notes.

## Dependencies

The README lists NumPy, SciPy, and `secsy`. Live imports also require NetCDF4
and ApexPy for the exported classes. Manual figures add matplotlib and polplot;
the unexported factor implementation additionally imports `sksparse`.

`pyproject.toml` currently declares no runtime dependencies, so an editable
installation does not reconstruct the required environment.

## Boundaries

`icReader` consumes products; it does not build the IMAGE conductance dataset.
Product generation belongs to `icBuilder`, while downstream scientific analysis
belongs to consumers such as `icAnalyzer`.
